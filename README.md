# Claude 用量小鲸鱼挂件

Claude Code 桌面端的小鲸鱼挂件：**输入框上方一条用量摘要 + 一个面板入口**，
点开**侧边面板**看完整数据。数据全部来自本机、全部只读，不需要 API key，不上传任何东西。

这是 [DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)
的 Claude 版重做——原版挂在 DSH Web 界面右下角、显示 DeepSeek 余额；Claude 没有
「用 API key 查余额」的接口，所以这一版换成了 Claude 真正能读到的四类数据。

```
  > 工作间隙摸鱼中       5h 23% · 2h13m 后重置  +128 -34  [面板]
```

用量条**右侧**是摘要文字与「面板」按钮，**左侧**留了一块 16 列的字符画：
闲置时鲸鱼在睡觉，`z` 一个字母一个字母地蹦出来，攒满整格再「呼」一口气；
跑对话时换成 `>` 当鱼头，后面跟着她嘀咕的一句话——干活时说「工作间隙摸鱼中」
「悄悄摸鱼中」，忙时说「猛吃大白饭中」「再来一碗」，两句一组轮流换。
三种状态都是恰好 16 列，切换时后面的摘要文字不会左右跳。
终端没有 `Svg`，画的是同一幅字符画。
面板里另有一幅大立绘（原版素材内嵌），气泡里的台词按一天里的钟点变。

末尾的 `+128 -34` 是本会话的代码改动行数：`+` 用主题的 `diffAdded` 色、`-` 用
`diffRemoved` 色，一眼分得清。**它随 Edit / Write 实时更新**——用量条在渲染时读了
`totals`，而宿主在 `$.state.set` 时会重绘读过该值的绘制点，所以不必等定时刷新。
这一段只在「代码改动」口径勾上时才出现，没有改动时不画，不会留一个 `+0 -0`。
面板的「设置」页里可以把「代码改动」设成唯一口径——那一组是多选，选几项就
同时显示几项，按固定次序拼接。

## 显示什么

面板把 Claude 原生 `/usage` 与 `/context` 两块面的字段都搬了过来。只有这一种形态：
没有「简洁 / 详细」开关——精简版少掉的正是最该看的明细，想看少一点大可直接关掉面板。

| 数据 | 来源 | 说明 |
|---|---|---|
| **额度窗口 5h / 7d** | `$.session.usage()` | 订阅账号的 5 小时 / 7 天窗口百分比与重置倒计时 |
| **全部额度窗口** | `$.session.usage().rateLimits` | 按原生标题逐条列：Current session、Current week (all models)、Current week (Sonnet only)，网关窗口原样列出，每条配一条方块进度条 |
| **会话花费** | `turn.complete` 逐模型累加插件价目表 | 本会话累计美元数。引擎 `/cost`（`$.session.usage().cost`）只在某一款模型插件也没收录时兜底，并注明是估的 |
| **会话时长 / 轮次 / 代码增删** | `turn.complete`、`tool.call` | 墙钟时长按轮累加；Edit / Write 只数 diff 的增删行，不保留行内容 |
| **按模型用量** | `turn.complete` | 每个模型的 token、估算金额、轮次，按花费降序 |
| **上下文占用** | `$.session.usage().context` | 上下文窗口已用百分比与 token 数 |
| **上下文窗口与加载项** | `$.session.usage({ breakdown })` | 窗口上限与来源（模型自身上限 / 设置 / 环境变量）、自动压缩阈值，以及记忆文件、MCP 工具、自定义 agent、技能与斜杠命令的**数量**。逐项 token 数与 10×10 网格都不上屏——柱状图已按同一批类别着色，柱子的厚度就是那笔 token |
| **每轮消耗** | `turn.complete` 事件 | 每轮结束后的真实 token，按官方价格估算；默认不弹提示，可在面板打开 |
| **本地历史用量** | `~/.claude/projects/*.jsonl` | 今日 / 最近 N 天的 token 与估算金额，跨会话汇总 |
| **用量概览** | 本地扫描的 `overview`、`turnsDaily` | 会话数、消息数、总 token、活跃天数、峰值时段、常用模型六张卡（按宽度排成 1×6 / 2×3 / 3×2 / 6×1），外加一张与它们同框的热图矩阵 |
| **模型分布** | 本地扫描的 `byModel`、`modelDaily` | 逐日逐模型的堆叠柱状图（柱内按模型分段），外加每行一个模型的输入 / 输出 token 与估算金额；未收录价格时标「未收录价格」，不会被藏起来 |
| **本会话上下文占用** | `$.session.usage({ breakdown: 'summary' })` 逐轮记录 | 每轮一根堆叠柱，**柱高＝这一轮的 token 绝对量**，纵轴上限是自动压缩阈值（刻度按 `K` / `M` 写）；柱内按内容分类（系统提示 / 工具定义 / 记忆文件 / MCP 工具 / 自定义 agent / 对话消息）堆叠。柱子顶到轴顶＝马上要被压缩，柱内哪一类最厚＝窗口被什么占着。百分比读数按**模型完整窗口**算：1M 窗口里放 300K 就是 30% |

上下文柱状图**不翻页**：显示最近多少轮由画布宽度自己算——每根柱子的槽宽
不得低于 1.4px（对应 1px 柱宽 + 0.4px 缝），在这个下限之上能塞几根就塞几根，
永远贴住最新一端。面板宽就多露几轮，窄就少露几轮，图注里的轮数随之变化。
翻页按钮要求读者点两下才看得到前一段，而宽度本来就该自己适配。轮次热图
同理不翻页——它的列数随面板宽度增加，方块大小始终不变。

这个「裁到几轮」**只算一次**：`contextView` 是唯一出口，图注、图例、纵轴、
无障碍描述、终端上的字符图全部从它拿同一份结果。曾经面板侧写死 60 轮、
SVG 内部又按宽度裁一次，窄画布下就会出现「图注说 60 轮、图上只有 34 根」，
图例还会列出已被裁掉那几轮才有的分类；若被裁掉的那几轮里有高峰，纵轴也会
跟着被拉高、可见的柱子被压扁。

**纵轴按这一屏的峰值自适应**，左侧轴线顶端直接标出上界、底端标 0——读者看
柱子时视线本来就在画面里，不必再回到图注里找一个百分比。空出来的地方本身
就是「还有余量」，不再额外画一段空闲底色把柱子补满。

面板里的小鲸鱼**按一天里的钟点换情绪**，与额度无关：深夜睡着 → 早晨摸鱼 →
上午干活 → 午饭吃白饭 → 下午继续 → 晚饭再吃 → 夜里累了。额度回答的是「这个
窗口用掉了多少」，与角色此刻在做什么是两回事——深夜该睡就睡，不因为额度还空着
就让她一直精神抖擞；上午刚开工时额度可能已经过半，她也不该因此立刻变成吃撑的
样子。分隔点在整点，取本地时区。

鲸鱼从面板右下角起步，**默认固定 380px 宽**、高按 320/620 的画布比例算。早先
按面板宽度的 55% 算，结果窗口一横向压缩，画面里的主角就跟着缩水——读者只是把
窗口拉窄，鲸鱼不该因此变个大小。

**她固定贴在面板右下角，不再巡游。** 曾经按 `swimOffsetFor` 做三角波：一步
3 列、一步 6 秒，到左端折返。问题是面板每 30 秒自动重绘一次，读者看到的是
「鲸鱼每次刷新都往中间走一点、位置回不去」——一个该固定在右下角的立绘变成了
会漂移的东西。巡游的收益只是「看起来活着」，而这个挂件本来就靠数据刷新证明
自己活着；代价是位置不可预期。现在恒定贴右端。鲸鱼不翻转（素材朝左，镜像会
破坏气泡的指向关系）。

**立绘大小在设置页里调**，档位是 25% / 50% / 100% / 150% / 200%，默认 100%。
引擎没有滑块控件（只有 Button / Client / Code / Image / Input / Markdown /
Raster / Select / Svg 九种），所以「拖动条」做成一排档位按钮：点哪一档，立绘
立刻跳到那个比例，选中那档高亮，选择存进 `$.store` 跨会话保留。

只有**面板窄到放不下**时才缩：此时按可用宽度（约每列 8px）收缩，否则立绘会
溢出到面板外被裁掉（引擎的 `overflow` 只有 visible / hidden，没有滚动）。

**这个夹取要对缩放后的尺寸再做一次。** 基准尺寸在 49 列附近就夹住了
（380px ÷ 8px），但设置页的档位乘在它上面：80 列面板只有约 632px 可用，
200% 档是 760px——早先只夹基准、不夹缩放，多出的 128px 被直接裁掉，鲸鱼
只剩左半边。现在算完 `宽度 × 档位` 之后按可用宽度再夹一次，高度跟着重算
（否则 `preserveAspectRatio` 会留白并上下居中，看上去像在抖）。

「右下角」要真的贴着底边：面板的根容器按正文可用行数（`scroll.bodyRows`）
撑满高度，中间留一个可伸缩的占位，把鲸鱼与脚注压到底部。不这么做的话，
整棵树只有内容那么高，窗口一拉高，鲸鱼就贴着最后一行内容悬在半空、底下
空出一大片。只对停靠（dock）的面板这么做——内联面板的高度本来就由内容
决定，撑满会凭空拉出一长条空白。

### 鲸鱼泡泡：常驻 + 轮播

鲸鱼旁边的思维泡泡**一直显示**，不需要点。内容每 6 秒换一页，每页三行说
同一件事，其中**一行字号更大，是这一页的主角**：

| 页 | 第一行 | 主角 | 第三行 |
| --- | --- | --- | --- |
| 额度 | 5 小时 · 7 天占用 | 5 小时百分比 | 重置倒计时 |
| 上下文 | 上下文占用 | 占用百分比（按模型完整窗口） | 已用 token |
| 本会话 | 本会话轮次 | 花费 | 代码增删 |
| 本地 | 今日消息数 | 今日花费 | 跨期总花费 |
| 人设 | 台词 | 台词 | 台词 |

**主角不一定在第二行。** 早先按「第二行永远是主角」硬排，额度页于是把
「5 小时窗口 23%」八个字塞进 46px 那一行——需要 355px，而椭圆在该基线处
只有 271px，超出的 84px 直接被描边压住。现在每页自己指明主角行，主角位
留给最短的那个数字（百分比、金额）。`tests/node.run.mjs` 有一条测试按椭圆
方程逐行验算全部五页的宽度，不只是人设页。

前四页只在有数据时出现。**第五页是人设页**，与数据无关、永远在最后，说的是
DeepSeek 鲸鱼娘的口头禅，并随情绪换一套：

| 情绪 | 本地钟点 | 第一行 | 主角 | 第三行 |
| --- | --- | --- | --- | --- |
| sleep | 00:00–05:59 | DeepSleep | 梦里管够 | 做梦吃米饭 |
| idle | 06:00–08:59 | 探索未至之境 | 吃白饭 | 摸鱼中 |
| working | 09:00–11:59 | 内心 OS 很长 | 想吃饭 | 已思考 4s |
| busy | 12:00–13:59 | 胃口特别大 | 再来一碗 | 偷吃 Token |
| working | 14:00–17:59 | 内心 OS 很长 | 想吃饭 | 已思考 4s |
| busy | 18:00–20:59 | 胃口特别大 | 再来一碗 | 偷吃 Token |
| tired | 21:00–23:59 | 活没干完 | 先吃饭 | 到点就下班 |

两顿饭各给一段 `busy`，正对「吃白饭」这个梗。

**情绪只体现在台词上，配色不跟着变。** 气泡始终是原图那一套白底蓝字
（`#FFFFFF` 底、`#203170` 描边）。曾经按情绪换底色——额度过半转暖、夜里更暖、
深夜转灰蓝——一天里不断变色，读者换一个时段就要重新适应一次，而它既不是数据
也不是状态。

### 这些台词从哪来（2026-10-29 重新核对）

**「大肥鱼」是她自己认领的名字。** 2026 年 8 月 DeepSeek 做了品牌拆分：黑鲸划给
面向企业的 Harness（就是「D老师」），消费级主品牌换成蓝鲸。V4.1 Flash 上线识图
后，有网友把蓝鲸 logo 丢进对话框考它认不认得自己——它先一本正经地分析「用户上传
了一张蓝色大肥鱼的图片」，隔了两秒才反应过来「这不就是我自己吗」。这个外号是模型
自己张嘴安上的，萌点就在「认出来了，但愣了两秒」。（[17173《正惊解梗》](https://news.qq.com/rain/a/20261023A08JBY00)，2026-10-23）

**B 站上的原始标题与热评**（2026-10 用 `api.bilibili.com` 的公开接口查的，只取标题、
简介与热评，不抓弹幕）。这个梗在 B 站的原话是「蓝色大肥鱼又吃大白饭了」「抓到偷吃
白饭的蓝色大肥鱼啦」「你这爱吃白饭的蓝色大肥鱼」「小肥鱼快来，这里有大白饭！」；
热评里有「西方 ai：肃正协议／东方 ai：白饭肥鱼」和「这 up 神了一天天啥也不干就喂
大肥鱼」。可见「白饭」「喂饭」是这个梗的第一联想——所以五档的主角行落在
「吃白饭 → 想吃饭 → 再来一碗 → 先吃饭 → 梦里管够」这条饭线上。

**饭学对应**：白饭 = token，吃饭 = 消耗算力 / 到点下班，摸鱼 = 走神，
摸鱼外包 = Agent 调用。「吃白饭」还带一点「便宜、白嫖、不干活」的自嘲——
DeepSeek 的 API 定价低到被叫「AI 界拼多多」，于是有「真当我是便宜货啊」这句
傲娇反击。这套对应让「吃白饭」与挂件要显示的 token 用量天然同构。

**萌娘百科「DeepSeek 娘」词条**（`zh.moegirl.org.cn/DeepSeek娘`）：
「探索未至之境」是 DeepSeek 官方 slogan（deepseek.com 平台页原文就有）；
「能够深度思考，对于每个现实人类的要求都会思考再三，有着长长的内心 OS」是萌点；
「喜欢吃白米饭和 Token，而且胃口特别大，总是吃不饱」直接支撑了 busy 档的前两行；
「打瞌睡（运作 sleep 命令）DeepSleep」是 sleep 档的第一行；
「工作的时候会把任务外包给其他 AI」就是 idle 档的「摸鱼中」。

### 两点重要澄清

**其一，这不是官方人设。** 2026 年 8 月网传一套 `【PERSONA_LOAD】CETACEA_LOLI /
FOOD_RICE / …` 的「DeepSeek 内置鲸鱼娘神秘代码」。崔亮做了跨模型对照实验证伪：
同样几个 Tag 丢给 ChatGPT 和 Grok 也能进入角色，把全部字符串换掉人格仍然出现，
Claude 看懂了但拒绝扮演。结论是「大概率没有内置」，那些 Tag 只是高信息密度的
结构化自然语言，细节全靠模型先验补全。（[原文](https://cuiliang.ai/posts/deepseek-whale-girl-role-dsl)，2026-08-17）

**其二，删掉了一句查无实据的话。** `tired` 档第三行原先写「测完告诉我」，配合
「我去吃饭，测完告诉我就行」这句号称「出圈口头禅」。用精确引号在必应搜
「我去吃饭」「测完告诉我」**零结果**，萌娘百科条目里也没有，只出现在一个二手
梗百科页面上（那个页面还写了「2026 年 8 月才发布 V4-Flash」这类精确日期，而
V4-Flash 实际 8 月 12 日就在报道里了，可信度不足）。已换成 17173 原文里有据的
「活没干完就惦记着下班」→「到点就下班」。

**台词长度由气泡几何锁死**：椭圆是 `cx 228 / cy 112 / rx 146 / ry 90`，三行
基线处扣掉描边后的净宽只有 269 / 271 / 198px，按 25 / 46 / 21px 的字号折算，
每行最多约 10 / 5 / 9 个汉字。SVG 不会
自动折行，写长了就被描边压住，所以 `tests/node.run.mjs` 有一条测试按椭圆方程
逐句验算宽度。

没有数据的页整页不出现，而不是画一行「—」占位——轮播里出现一页空话，
读者会以为界面坏了。什么数据都没有时，人设页仍在，泡泡不会空着。

**为什么不做成「点鲸鱼」**：点击区没法精确对齐立绘。`Svg` 的尺寸是 CSS
像素，`Box` / `Client` 的尺寸是字符格，引擎不给两者之间的换算，行高又随
字号变化（14~22px 都常见）。试过按 16px / 10px / 8px 反算行数，也试过
`100%`（`Box` 不吃百分比，会塌回一行），结果要么点不中下沿、要么塌成一条。
泡泡常驻把这个问题整个绕开：读者连点都不用点。

轮播的页号由时钟算出（`floor(now / 6000) % 页数`），不写状态——写状态会
额外触发一次重绘，而这里只需要知道「现在是第几页」。翻页靠一条专用的
`$.clock.every(BUBBLE_PAGE_MS, …)` 推 `$.ui.invalidate`。

气泡**没有尾巴**。曾经从椭圆左下甩出一条装饰线，既不对应任何数据，又容易
让人以为气泡漏了气；气泡靠位置（在鲸鱼左边）就足以说明「这是谁在说话」。
两颗小泡从大泡右下沿同一条射线依次变小，指向鲸鱼。它们要停在鲸鱼**外面**，
而鲸鱼是不规则的——逐像素解析内嵌 PNG 后，它最靠左的一处在画布
`y≈212` 一带，只有 **340**；早先代码注释里写的「鲸鱼占 x 378~620」是按
显示框估的，多算了 38px，于是小泡正好压上去 61 平方像素。现在的位置
（`321,226` / `347,265`）留出了余量，测试按实测的逐行左缘表守着。

`assets/preview.svg` 与 `assets/preview.html` 由 `scripts/make-preview.mjs`
从 `whaleSvg()` 直接生成，不再手抄——手抄的那份曾与代码脱节，尾巴删了以后
预览里还挂着一条断线。改了画面就跑一次：

```bash
node scripts/make-preview.mjs
```

### 与原生面板的差异

两项原生面板有、这里没有的，如实说明，不拿别的数字硬凑：

- **总耗时（API）**：引擎只提供每轮的墙钟时长（`turn.complete` 的 `durationMs`），
  没有单独的 API 耗时，所以这里显示的是墙钟时长。
- **子代理的轮次**：子代理在自己的循环里结束，主线程不汇总，所以面板的
  「本会话」那一行（轮次、花费、按模型用量）**不含子代理**。

**但本地历史统计是含子代理的**，两者口径不同，别拿它们互相比：

| 位置 | 数据源 | 含子代理 |
|---|---|---|
| 面板「本会话」、用量条、气泡 | `turn.complete` 事件（主线程） | 否 |
| 本地历史 / 用量概览 / 模型分布 | 扫描 `~/.claude/projects/*.jsonl` | **是** |

子代理烧掉的 token 是真实的，所以跨会话的账要算进去；而「这一轮花了多少」
是会话自己循环里的事，子代理不在其中。实测本机 30 天，子代理约占 output
token 的 10%。

（扫描时子代理日志**只被排除在「会话数」与「轮次」两个计数之外**——一次
`Task` 会产出各自的 `agent-*.jsonl`，按文件名数会把它当成多个会话；它里面的
`tool_result` 回填行也容易被误判成用户提问。token 与金额一分不少地计入总量。）

`/context` 的明细用 `summary` 粒度：全部本地估算，不发 token 计数请求，所以面板
每次重绘都不会打 API。需要 `full` 的精确计数时用原生 `/context`。

柱子的**高度**（token 绝对量）来自引擎的真实读数，而**柱内各分类的份额**是
`summary` 粒度的本地估算，两者不要当成同一精度看。

上下文图本身有三处细节：横轴标的是**轮次序号**而不是时间（逐轮间隔极不均匀，
按时间排会把两轮挤在一起、把隔了几小时的地方拉成长空档）；柱子多时数字会抽稀，
但首尾两根一定标出来；每次压缩的下一轮柱子左侧竖一条**灰色虚线**——压缩会让
上下文骤降，不标出来的话，读者会以为那是自己突然少用了。灰而不是橙：橙色在
冷色柱子里太跳，读起来像又一个内容分类；虚线只是个标记，它该退到背景里。

压缩标记取自会话日志里的 `compact_boundary` 行，是引擎自己记下的事实（压缩前
多大、摘要多大、自动还是手动），不是从占比变化猜的。图注里会写出这一屏压缩了
几次，以及最近一次的「36.7万 压到 2.8万」——括号里的后者是摘要本身的体积，不含
系统提示与工具定义，所以它比压缩后第一轮的实际读数小得多，两者别放在一起比。

概览、上下文、模型三块共用一套圆角外框与同一支底色。底色、边框、选中态文字
一律写成**主题键**（`userMessageBackground`、`promptBorder`、`text` 等），由
绘制端按实际主题解析——所以 `/config` 的 `theme` 是默认的 `auto` 时也跟着系统
走。曾经这里写了两套十六进制、按 `theme` 的值二选一，而 `auto` 的含义是
「跟随」：插件不知道跟到的是深还是浅，于是永远挑深色那套，浅色界面里整块
深蓝黑。主题仍在面板打开期间缓存，换主题要重开面板才生效。

图表是 SVG 里的十六进制，引擎解析不了，只能由插件先挑一套：显式 `light` /
`dark` 各用一套，`auto` 与读不到时用**中等明度**的中性色板——每一支在深色
内嵌底与浅色内嵌底上同时过图形元素的 3.0，宁可两边都只到刚过线，也不赌一边、
在另一边糊成一片。`theme.isLight` 因此是三态：`true` / `false` / `null`。

「用量概览 / 模型分布 / 本会话上下文占用 / 设置」四个页签与它们的内容在
**同一个外框**里：页签是这个框的标签栏，内容是本页的读数，分开画成两个框会让
人以为页签是面板级导航、内容又是另一块卡片。用量条口径与两个开关收在「设置」
页里，不再摊在面板最下方与几页内容并列。

设置页里的每一项都是**开关**：亮着的是开着的。不做「按一下换标签」的动作
按钮——同一组里混两种语义，读者就没法从「亮不亮」判断当前状态。用量条口径
点到最后一项时会弹一句提示而不是静默无视，否则界面对那次点击毫无反应，
看起来像按钮坏了。凡是「没存过就用什么」的地方一律引用 `DEFAULT_PREFS`，
不写字面量：两处各写一个数，迟早会分叉。

**页签与开关按钮自己就是那块可见的方块，外面不套带边框的 `Box`。** 引擎文档
写明 `Button` 在桌面端画成原生按钮，命中区只包住它自己的内容；`Box` 的边框
在按钮之外，那一圈永远点不到——这正是「看着是个框、点上去只有文字有反应」的
原因，只补内边距救不了。所以选中与未选中都保留底色，区别在明暗：选中的那块
底色更亮、文字加粗，未选中的也仍是一块方块，只是暗下去。字符界面里圆角边框
与整块可点不可兼得，这里选后者。

选中态的文字取主题键 `text`：它在激活底上是正文级的对比（深色 9.44、浅色
20.47），而且跟着主题走。未选中态保持低调：只有一档更暗的底色加 `dimColor`，
不加边框。

模型分布与上下文占比页的内容各自装进**更深一档**的圆角块
（`composerSidebarBackground`）：图表、图例、表各成一块，读起来是「嵌进页面
的一块内容」，而不是又浮起来一层。方向与页签的激活态相反是有意的——页签是
「被选中所以往前浮」，图表块是「嵌在页面里」，往后退一格才分得出层次。

「代码改动」口径勾上之后才在用量条上显示增删，且 `+` 用 `diffAdded`、`-` 用
`diffRemoved` 两种颜色；没勾时两者都不出现。文字摘要里不拼改动——拼进去就
没法分色了。

### 哪些数字是读数，哪些是估算

这条界线写在下面的表里，不占面板本身的空间：

| 类别 | 精度 | 说明 |
|---|---|---|
| 额度窗口百分比、上下文占用百分比、token 计数 | 引擎读数 | 宿主或日志直接给，不经过本插件换算 |
| **所有美元金额**（面板、用量条、提示气泡） | **估算**，前面带 `≈` | 按官方价格表乘出来，不是账单 |
| 柱内各分类的份额 | 估算 | `summary` 粒度的本地启发式，不发请求 |
| 本地历史 | 本机范围 | 只覆盖这台机器的日志 |

没有一笔金额来自账单，所以 `≈` 不是可关的装饰：关掉它，界面就会把估算冒充成
消费记录。想做账请以 Anthropic 控制台为准。

**「本会话花费」优先按插件自己的价目表算**，面板顶部、用量条、气泡三处同一个
数。早先它取引擎 `/cost` 的会话累计，而引擎只认 Anthropic 第一方的价目表：遇到
第三方网关的模型名它会**按默认模型的价格**估（引擎里这个字段的原话是
"costUSD is a guess at the default model's rate"，原生 `/cost` 也会打一行
"costs may be inaccurate due to usage of unknown models"）。实测同一批 token：
DeepSeek Flash 按官方价 $3.05，引擎按默认模型估成 $258.98。

现在逐模型累加 `byModel[].cost`（`turn.complete` 写入时已按价格表算过）。只有
某一款模型**插件价目表也没收录**时才退回引擎读数，并在金额后面注明「含引擎未
收录的模型，按默认模型价估」——那种情况下这个数本来就不完整，少算一笔比显示
一个偏高的估更糟，读者需要知道。

注意这与 `priceOf` 是两回事：插件自己给 DeepSeek 收录了价格（概览与模型页
用的是它），引擎那边仍然不认识，两件事不能混。

「用量概览」的数字来自本地日志扫描，不是账号级别的统计：它只覆盖这台机器上的会话，
不含其他设备或 claude.ai 网页端。这和原生用量页的口径一致（原生页也标注了这一点）。

本地历史由定时扫描更新，没有手动刷新按钮：每 15 秒看一眼，距上次扫描超过 5 分钟
才真的重扫。增量缓存让这次重扫只读刚写过的几个日志文件——实测 400 天、727 MB
的日志，冷扫描 3.4 秒，有缓存后 84 毫秒；平时 5 分钟也就读几 MB。

「轮次历史」是一块热图矩阵：每列七日竖排、列与列从左到右是连续的周，方块是
圆角正方形。**方块大小固定，面板越宽就多露出几周**——一个方块永远代表一天，
读者不必在不同宽度下重新适应格子的大小；图注里的「最近 N 天」因此随宽度变化，
它写的就是这块矩阵实际覆盖的范围。

默认色深映射消息数，可以切换到「轮次」（用户真正输入的次数）。两个量共用同一块
矩阵，形状可比，换口径只是换一把心里的标尺。图注一行右对齐，同时给出口径、天数、
总量与峰值。

**0 值格子用一层中性底色**，与「用量最少的那一档」分属两个体系——这天没有
用量，不是用量少。色标本身用同一支蓝的**不透明度**分五档，而不是五支写死的
实色：SVG 背景透明，同样的不透明度在深色主题下呈现为暗蓝、在浅色主题下呈现
为淡蓝，两种主题都读得出深浅，不必去探测当前是哪套主题。

「用量概览」顶部六张卡与热图属于**同一个编组**。六张卡的列数随宽度在 6 / 3 / 2 / 1 之间
切换（即 1×6、2×3、3×2、6×1 四种排法）。每张卡各带一个圆角框，宽度按列数算出同一个
整数，**不用 `flexGrow` 均分**——那会让「值」长短不同的卡算出带零头的宽度，六张卡的
右边缘就参差不齐。卡片之间的横向与纵向缝隙都用 1 列 / 1 行：只在横向上留缝的话，
换行之后两行卡片会贴在一起，看起来像一整块被切开。

**模型分布**是一张按天或按周的堆叠柱状图：柱内按模型堆叠，配色以 DeepSeek 蓝
为核心沿色相铺开。段序按窗口内总量固定，所以颜色与模型的对应跨天稳定。

范围可选 **30 / 60 / 180 / 365 天**，粒度跟着范围自动切：前两档按天（30 根、
60 根），后两档按周（约 26 根、52 根）。粒度和范围绑死是有原因的——900px 画布下
365 根柱子每根只有 2.4px，柱内各段分不开，整张图会糊成一片。365 天仍按周而
不是按月：52 根周柱子每根约 16px，比 60 天按天那档（14.4px）还宽，而按月只剩
12 根，「这个月哪一周花得多」就看不出来了。图注会写明当前用的是哪种粒度，
因为同样 26 根柱子，「按天 26 天」和「按周 26 周」说的是完全不同的时间跨度。

按周分桶时以**周一**为一周之始（周日归上一周）；桶里的 token 直接相加，不取日均，
读者问的是「这一周花了多少」，日均会把「这周用了七天」和「这周只用了一天」画成
一样高。

横轴标的是每根柱覆盖区间的起始日，两种粒度都写 `MM-DD`：按周的范围最长一年，
跨年的两根柱子会各自写出月份，年份在这个跨度里仍是噪音；完整月-日则让读者
能对上日历。柱子多时标签按**实际像素宽度**抽稀，不用固定值。首尾两个日期
一定标出，读者才知道这一段是哪两天。

同一款模型的几种写法会**归并成一行**：网关会把 `deepseek-flash`、`DeepSeek-Flash`、
`deepseek-v4-flash`、`deepseek-v4-1-flash` 记成四个名字，拆开显示只会让人以为是
四款不同的模型。归并按「厂商 + 档位」两级，认不出的写法原样保留。

下方是一张对齐的表：模型、输入、输出、费用各占一列。列宽不是写死的数字，而是
**按这一屏的读数现算**：每列取该列最长的那个读数（按显示宽度），夹在上下限之间，
剩下的宽度全给模型名。取最长而不是取最短——以前按最短定宽，`8.0万` 撑出的列
放不下 `21.50亿`，长读数被截成 `21.5…` 挤成一团。列与列之间留两格，相邻两列
的数字不会贴成一个长串。

**每个单元格是一个定宽 `Box`，列宽由引擎的布局决定。** 早先每格是一个
`<Text>`，宽度靠 `padCell` 在行尾补空格撑开；只要绘制端把行尾空白裁掉
（`trimEnd` 是终端渲染的常见做法），列宽就塌回内容宽度——`qwen3.8-27b` 补
12 格、`deepseek-v4-flash` 补 7 格，两行画出来一样宽，四列全歪。现在盒子
的宽度与文字长短无关，绘制端裁不裁行尾空格都不影响对齐。

**整表的宽度要扣掉页框的 4 格。** 明细表套在「页签 + 内容」那个大圆角框里，
框的边框（2 列）与左右 `paddingX`（各 1 列）不属于这张表。忘了扣的话，整张
表比可用宽度宽 4 格，超出的部分被压缩，每一行按各自的折行点断开，表头与
数据行就全对不上——这比列宽算错更难看出来。

**四列一律左对齐。** 数字右对齐时，同一列里的 `8.0万` 与 `21.50亿` 位数不同，
左边参差不齐，扫读时每一格都要重新找起点；左对齐后起始位置固定，纵向扫一眼
就对得上。模型名前的 `■` 与表头对应位置的空格都放进 `CHIP_COLUMN`（2 格）
宽的盒子里——`■` 的东亚宽度属性是 Ambiguous（多按 1 格、CJK 环境按 2 格），
不猜它到底几格，两边用同一个盒子就不会错位。金额只写数字、不带 `≈`；
没有公开价格的模型记一个 `—`，由表下的脚注说明它的含义，而不是把整列撑成
一个长句。

输入口径含缓存读写，与柱子的段高一一对应。

### 关于第三方模型的金额

价格表收录 Anthropic 第一方模型，外加三款常见的第三方模型：

| 模型 | 输入 | 输出 | 缓存读 | 来源 |
|---|---:|---:|---:|---|
| DeepSeek Flash | $0.15 | $0.60 | $0.003 | 官方价，非高峰 |
| Qwen3.8 27B | $0.04 | $1.35 | $0.018 | OpenRouter 基础价 |
| Kimi K3 | $0.239 | $11.936 | $0.21 | OpenRouter 基础价 |

单位都是美元 / 每百万 token。三款都 **不套 Anthropic 的 1.25x / 0.1x 缓存换算**——
它们的缓存折扣比例差得很远（DeepSeek 2%、Qwen 45%、Kimi 88%），所以逐家给数字，
也都不单独收缓存写入费。

DeepSeek Flash 的型号在网关里写法不统一（`deepseek-flash`、`DeepSeek-Flash`、
`deepseek-v4-flash`、`DeepSeek-V4.1-Flash-1017` 都出现过），所以按「含 deepseek
且含 flash」识别，大小写不敏感；展示时这几种写法会归并成一行。DeepSeek 在 UTC
工作日的 01:00–04:00、06:00–10:00 收双倍价，所以界面上的金额是下限，不会高估。

其余第三方模型（GLM、DeepSeek 的非 Flash 型号等）的 token 照常统计、照常出现在
模型分布页，但金额记一个 `—`——拿别家的价去套只会给出错误数字。要再收录一个模型，
把定价加进 `hooks/pricing-data.mjs`（只有这一处——面板与扫描脚本都从它读）。

## 安装

本插件是 Claude Code 的 **mod**（function hooks 插件），需要 Claude Code **2.1.275 或更新版本**
——更早的版本没有这套 mod 接口。

### 一条命令

在 Claude Code 里输入：

```
/plugin install whale-usage --marketplace YuEr159/claude-whale-widget
```

仓库是公开的，自带 `.claude-plugin/marketplace.json`，引擎会先把市场加进你的用户设置
再装插件，不必自己 `git clone`。安装范围默认 `user`，装一次，所有会话都带着。

想分成两步也行：

```
/plugin marketplace add YuEr159/claude-whale-widget
```

```
/plugin install whale-usage
```

不在 Claude Code 界面里时，用命令行等价写法：

```bash
claude plugin install whale-usage --marketplace YuEr159/claude-whale-widget -s user
```

`-s` 可选 `user` / `project` / `local`。本插件挂在输入框上方与侧边面板上，是跟着你
这个人走的，`user` 最合适；只在某个仓库里用时才选 `project`。

装好之后：

- 输入 `/whale` 打开侧边面板；
- 输入 `/whale-band` 显示 / 隐藏输入框上方的用量条；
- 面板里可以多选用量条口径、在模型分布页切换统计范围，开关轮次费用提示与用量条
  （都在「设置」页签里）。
  隐藏用量条后，面板会弹一句 `/whale 可以呼出当前面板哦！`——入口没了，得告诉人怎么叫回来。

### 本地开发

改代码时不必每次都推上去再装，两种方式看目录：

**指定目录启动**——目录里改了什么，下次启动就是什么：

```bash
claude --plugin-dir "/path/to/claude-whale-widget"
```

**丢进会话的 mods 目录**——引擎在本轮结束时加载，之后改文件自动重载：

```bash
cp -r . "$HOME/.claude/dev-mods/<会话 id>/whale-usage"
```

`<会话 id>` 换成桌面端当前会话的 id，展开 `~/.claude/dev-mods/` 就能看到。

也可以把目录写进环境变量 `CLAUDE_CODE_PLUGIN_DIRS`，一次挂多个插件目录。

### 更新已安装的插件

**这是最容易踩的坑。** 插件从本地目录安装时，`plugin install` 会把文件
**复制**到 `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`，之后
加载的一直是那份副本。直接改仓库里的源码，`/reload-plugins` 也不会生效——
它重载的是缓存里的旧文件。

而 `plugin update` 只比较**版本号**：版本号没变，它回答「已是最新」，
不会重新拷贝。

所以仓库里装了 `pre-commit` hook，每次提交自动把版本号加一（见
`scripts/bump-version.mjs`），`plugin update` 因此总能认出新代码：

```bash
claude plugin marketplace update whale-usage-marketplace
claude plugin update whale-usage
```

然后**完全退出并重新启动桌面端**。注意 `/reload-plugins` 在部分环境里会被
禁用（日志出现 `reload_plugins disabled: a managed MCP policy governs plugin
servers at spawn only`），那时只有重启进程才会加载新版本。

克隆仓库后先装一次 hook，否则版本号不会自己涨：

```bash
node scripts/install-hooks.mjs
```

`plugin details` 里的 `Hooks (0)` 是**正常的**：它只数声明式 hook，不数
`hooks/hooks.json` 里 `modules` 指向的 JS 模块。插件是否真的挂上了，看
`claude plugin validate <目录>` 能否列出那 11 个 hook。

### 卸掉

```
/plugin uninstall whale-usage
```

市场本身不会跟着删，还在的话用命令行收走：

```bash
claude plugin marketplace remove whale-usage-marketplace
```

## 怎么测

开发时用桌面端自带的引擎跑测试最准——它比 npm 版的 `claude` 新，规则也更严：

```bash
# Windows 上桌面端引擎的位置
ENGINE="$LOCALAPPDATA/Claude-3p/claude-code/<版本>/<哈希>/claude.exe"

"$ENGINE" plugin validate .   # 契约校验：名字、state 归属、调用了哪些接口
"$ENGINE" plugin test .       # 单元 + 渲染测试
npx --package typescript@5.6 tsc -p .   # 类型检查
node --test tests/node.run.mjs          # 不依赖 CLI 的等价测试
node scripts/bump-version.mjs --check   # 当前版本号
```

版本号的递增逻辑有单元测试覆盖（末位进位、拒绝非法形状）：

```bash
node --test tests/version.run.mjs
```

## 数据取不到时

| 情况 | 表现 |
|---|---|
| 没有订阅额度窗口（API key 计费、第三方网关） | 额度相关的两项口径各自表态：勾「额度窗口」时显示「无额度窗口」，勾「5h + 7d」时不显示（没有百分比可画）。不会互相顶替，也不会因为关掉其中一项条子毫无变化 |
| 用的是第三方模型 | token 照常统计。DeepSeek Flash 按官方价估算；其余型号显示「未收录价格」，不会拿别家价格硬套 |
| 本机没有 Node | 本地历史一栏报错，其余数据照常 |

## 致谢与借鉴

面板的「上下文构成」读法借鉴了 [bowenliang123/dsh-context](https://github.com/bowenliang123/dsh-context)
（Apache-2.0）的设计理念：上下文不是一个百分比，而是一个由若干类内容拼起来的窗口，
逐轮记录它的构成，才看得出窗口为什么变满。本仓库没有复制它的任何代码——宿主 API
完全不同（那边是 cordis 会话投影，这边是 `$.state` + `$.session.usage`），
只借了「逐请求留构成、按类堆叠着色」这一条思路。

## 与 DeepSeek 原版的差异

| | DeepSeek 原版 | 本版 |
|---|---|---|
| 宿主 | DSH Web 界面 | Claude Code 桌面端 mod |
| 位置 | 右下角常驻、可拖拽 | 用量条左段的字符画 + 侧边面板（大立绘在面板底边） |
| 主数据 | 余额（官方接口） | 额度窗口 / 会话花费 / 上下文 / 本地历史 |
| 画面 | 位图 cut-out + 代码绘制的 SVG 气泡 | 用量条只画鲸鱼本体；面板内嵌原图 + 代码绘制的气泡 |
| 取数 | 需要 API key 或平台登录态 | 本地 `$.session.usage()`，零凭据 |

原版有拖拽吸附、按压音效、自定义角色与台词。桌面端的绘制元素没有位图 `Image`，
也没有指针拖拽事件，这些在 Claude 版里用「用量条 + 侧边面板 + 表情」替代。
